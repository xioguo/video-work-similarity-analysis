# 视频作品相似度分析技能

用于比较两条或多条视频作品，结合完整口播、叙述结构和抽帧画面，生成带时间码、可回放、可复核的中文证据报告。

当前技能版本：**证据方法 v2.0**；内容计算方法：**content-v3**。

## 核心变化

把两个问题分别回答：**作品内容有多相近**，以及**相近之处能否支持复制某位作者个性表达的判断**。

- 全部有效口播层：产品事实、推广流程、操作步骤和表达均可计入内容相似；通用模板和重复观点按公开规则处理。
- 个性表达候选层：单独核查独特钩子、评价、隐喻及组合；内容相同不自动证明独创、来源或未经授权取用。
- 同义改写计入：字符不同、含义基本相同也算相近；对象、目标或具体型号不对应的部分保留差异。
- 双向覆盖：分别报告A有多少内容可在B找到，以及B有多少内容可在A找到。
- 素材独立核验：像素和画面哈希只用于筛选候选，连续素材复用需要进一步核对；未知不填成0%。

## 内容相似度

| 描述性指标 | 权重 | 计算范围 |
| --- | ---: | --- |
| 保序结构 | 37.5% | 共同动作的最长保序链，占方向源作品有效动作的比例 |
| 语义动作覆盖 | 37.5% | 每个动作预列语义要件，按实际命中比例折算 |
| 语义文字覆盖 | 25% | 实际同义原文片段的位置并集，占方向源作品有效文字的比例 |

两个方向分别加权，概览值取双向综合的均值。动作数量和文字篇幅使用同一批语义标注，不能把它们宣传为两份独立复制证据。

**该分数是描述性内容指标，不是抄袭概率，不再机械按60%自动判断抄袭。** 严重局部表达或连续录屏证据须显著展示，不能被整片均分掩盖。

旧“四项加权v2.1”的像素20%已退出主综合；旧数与新数不能直接比较，旧语义标注需要按新口径重新审计。

## 安装技能

把本仓库克隆到你的技能目录，文件夹名称使用 `video-plagiarism-check`：

```bash
git clone https://github.com/xioguo/video-work-similarity-analysis.git ~/.codex/skills/video-plagiarism-check
```

若该目录已经存在，请先检查已有自定义内容并选择合并方式。其他支持 `SKILL.md` 的工具可按各自技能目录规则安装。

安装后，在新对话中提供两条作品链接或本地视频，并调用 `video-plagiarism-check`。例如：

> 按视频作品相似度分析技能比较两条作品，完整核查口播和素材。报告双向内容覆盖，逐处列出相近表达、不同之处及来源证据，生成带时间码的对照页。

## 文件结构

```text
SKILL.md
references/
  material-analysis.md
  semantic-text-coverage.md
scripts/
  frame_similarity.py
  score_content.py
```

- `SKILL.md`：取证、双层双向覆盖、来源核查和证据分级。
- `references/material-analysis.md`：抽帧、像素筛查和连续画面核查方法。
- `references/semantic-text-coverage.md`：同义标注、位置并集、去重和机器数据接口。
- `scripts/frame_similarity.py`：比较已有采样帧，输出像素与外观候选；不再接收旧内容分来合成抄袭判断。
- `scripts/score_content.py`：校验人工审计的引文和位置，计算双向内容覆盖与结构；不自行判断同义或原创。

## 运行脚本

需要Python 3.9或更新版本；图像筛查依赖Pillow，内容聚合脚本使用Python标准库。

```bash
python3 -m pip install -r requirements.txt
python3 scripts/frame_similarity.py \
  --a-frames /path/to/A/frames \
  --b-frames /path/to/B/frames \
  --output /path/to/frame-screening.json \
  --interval-a 5 --interval-b 5
```

采样帧目录不要混入封面、网格或派生对照图。像素比较默认全图统一为320×180 RGB并使用Lanczos重采样；B各帧选最佳A后汇总。方向、采样间隔和公共背景影响必须说明。颜色接近不证明同一素材或同一录屏。

完成实际原文和语义证据标注后，再聚合内容数据：

```bash
python3 scripts/score_content.py \
  --input /path/to/audited.json \
  --output /path/to/content-score.json
python3 scripts/score_content.py --self-test
```

输入采用 `A_units`、`B_units`、`structure_pairs` 等字段；每项保存时间、原文、要件及另一作品证据，文字片段保存归一位置。详见 `references/semantic-text-coverage.md`。脚本只核验引文存在、区间和算术，不能代替人工判断证据是否同义。

旧图像脚本的 `--component-scores` / `--weights` 合成接口已停用；旧配置需要迁移为仅筛查配置，不能静默沿用像素综合公式。

## 报告交付

- 开场概览及两个方向的内容分、分子分母和方法版本。
- 逐段原话与时间码、相同和不同语义、内容属性与复制证据强度。
- 个性表达候选与已核实来源分开，来源未知保持未知。
- 封面和候选连续片段对照图、抽帧范围和未覆盖部分。
- 原始人工标注、复算脚本与JSON结果。

## 使用边界

完整流程还需要可用的视频获取、音频转写和证据复核能力；本仓库脚本不下载视频，也不执行语音识别。

人工分段、语义要件和抽象层级仍包含判断；计算可重跑不代表标注绝对正确。未核实的公共脚本、原画、素材身份或授权须列为待核查。没有发现对应不等于已证明独立创作；同款背景、角色或软件界面也不能直接证明搬运。

目前没有完成足够真实标注样本的准确率、权重或判定阈值校准。自检仅验证同义标注聚合、区间去重、顺序和未知状态等计算行为。

本仓库仅发布通用技能和脚本，不包含案例视频、实际审核材料、账号凭据或本机配置。
